# 结论总表（FINDINGS）

> 本文是全部工作的**结论层**。过程、A/B 实验、失败路径都不在这里。
> 每一个数字后面都有可复现的命令，见 [`MEASUREMENT.md`](MEASUREMENT.md)。
>
> 最后核对：2026-11-10。

---

## 1. 一句话结论

**相机连接层已闭环**（零主动断链、零拥塞丢帧、零花屏解码错误），
**消费端时间戳已稳定**（视频重建 20fps CFR，音频不再重建 PTS）。

**唯一未闭环项：相机 `wlan0` 出口周期性停滞 4–15 秒。**
表现为录像偶发跳一下 —— **不是断流、不是花屏**，且不在本项目的可修范围内。

## 2. 问题 → 根因 → 解法

| # | 现象 | 根因 | 解法 | 状态 |
|---|---|---|---|---|
| 1 | 控制面活着，画面全黑 | `RTPInterface` 发送失败后只摘 RTP/RTCP 通道，**不关 TCP** | P5 `shutdown(SHUT_RDWR)` 干净断链 | ✅ |
| 2 | TCP 半帧 / 部分写 / FIFO 短写 | 非阻塞 `send` 未处理部分写；FIFO `write` 非原子 | P7 `sendmsg` 原子帧 → P11 用户态队列 → P9 `write_all()` | ✅ |
| 3 | 花屏 / 竖向拉丝 | **IDR 被静默截断**（`ByteStreamFifoSource` 读块 4096B 太小 + `StreamParser` 读余量不足） | P12 4096B 读块 + P13 8192B 最小读余量 | ✅ 43/43 IDR byte-exact |
| 4 | 相机因瞬时拥塞**主动断链** | 输出队列 192KB 满即 `shutdown` | P18：队列 512KB、按整帧发送、满则丢帧不断链 | ✅ 30min PASS |
| 5 | 拥塞丢帧破坏 GOP 造成花屏 | `drop-oldest` 只保证落在**完整 NAL 起点**，不保证落在 **IDR** | P18b：队列满时已入队数据一字节不动，只丢后续新帧直到 SPS/PPS/IDR | ✅ v0.5.1 |
| 6 | 1–2 秒 PTS 段内空洞 | `-use_wallclock_as_timestamps 1` 按 socket read **批量打戳** | P15：保留 wallclock 作 demux 源，输出侧 `-bsf:v setts` 重建 20fps CFR | ✅ |
| 7 | **音频段尾截断**（AAC-T） | `-af asetpts=N/SR/TB` 按"送达样本数"重建 PTS，丢 k 帧则时间轴永久少 `k×64ms` | 删除该参数 | ✅ 187/187 段零坏段 |

## 4. 未闭环：相机 `wlan0` 出口停滞

**症状**（30 分钟内至少 3 簇）：

- 相机侧 `P11` 队列峰值 268,076 B，但日志**始终 `connection kept`**；
- `p5=0 / teardown=0 / drop=0` —— 连接层完全干净；
- 下游 `#timeout=4` 触发 go2rtc 重连一次 → 录像双写重叠或段内 ±帧 → 回放跳一下。

**定位**：`wlan0` 射频 / MT7601 驱动 / AP 省电策略 / 单核 CPU 调度。**不在 `rRTSPServer`。**

**已排除**：

| 假设 | 排除依据 |
|---|---|
| 信号弱 | 4 次停滞时刻信号均 −62~−70 dBm、`retry=0` |
| 连接层缺陷 | 该窗口 `p5/teardown/drop` 全 0 |
| 发送队列太小 | 峰值 268KB < 512KB 上限 |

**下一步唯一动作** —— 在停滞发生时刻抓四项地面真值：

```bash
ssh root@<CAMERA_IP> 'cat /proc/net/wireless; iw dev wlan0 station dump; \
  cat /proc/loadavg; grep MemFree /proc/meminfo'
```

判读：

- `tx` 不动 且 `loadavg` 低 → **射频 / 驱动 / AP**
- `loadavg` 飙高 或 `MemFree` 极低 → **CPU 调度饥饿**
- `retransmit` 暴涨 → **空口重传**

已知线索：停滞时 `loadavg` 6.6–8.1（单核超载约 7 倍），`tx` 5 秒窗口 ≈0 B 后 500–800 KB 积压倾泻 —— 呈调度饥饿特征。

**终局方案：有线相机。**

## 5. 禁改清单

> 这一节是从多次翻车里换来的。改动前请先读。

1. **不要把 go2rtc `#timeout` 改大。**
   P18c 试过 15 秒，30 分钟内 2 次 `Ffmpeg process crashed unexpectedly`，比 4 秒严重得多。
   机理：`timeout=15` 让 go2rtc 在相机停滞时既不重连也不出数据，下游 20 秒看门狗直接杀进程 ——
   把"4 秒小跳"换成"20 秒硬中断"。

2. **不要回到 P14b / P16 / P17 的消费端时间戳方案。**
   三轮均被生产数据证伪。**不要把 `-af asetpts=N/SR/TB` 加回 record**，它是 AAC-T 的根因。

3. **不要在拿到相机 Wi-Fi 证据前动 `rRTSPServer` 任何参数。** 连接层已无可修。

4. **不要把"分段连续"当成"画面连续"。** PTS 完美不等于无跳变。

## 6. 被证伪的方案（工程纪律记录）

> 保留这一节不是为了自嘲，是因为**下一个接手的人一定会想重试其中某一条**。

| 方案 | 期待 | 实际 | 结论 |
|---|---|---|---|
| P14b：直接删 record 路 wallclock | 消除 1–2s 空洞 | 真实 **3.5 分钟断流**，全局最大空隙 218s | 撤回 |
| P16：`aresample=async=1` 填静音 | 音轨连续 | 断链时补 ~4s 静音，首包 PTS 跳到 4.076s，容器膨胀到 14.5s | 撤回 |
| P17：双 `-bsf:a setts` | 音视频同步 | 断链后音视频计数器失步（`a_first=56.570s`） | 撤回 |
| P18c：`#timeout=15` | 减少重连 | 2 次 ffmpeg 崩溃、56 行错误 | 回滚 |
| `ipc_cmd -O OFF` 关云台 | 降低 rmm CPU | 命令成功但 CPU 无变化，`0x103c` 不在 rmm 处理表内 | 证伪 |
| P23：rmm 直连 FIFO（v1） | 零拷贝 | CPU −88% 但崩溃链（hook 内阻塞 / 递归 `memcpy`） | 回滚，P24 重做后成功 |
| `signalstats YDIF` 判绿屏 | 自动判花屏 | 近距运动**误报**、持续静态拉丝**漏报** | 判据作废，改空间梯度 |
| 自研 minimal 媒体进程替换 rmm | 省 15–25% CPU | 无 `libmpi.so`、管线不可分割、主线程无干净截取点 | 放弃 |

**两条判据教训**：

- 单靠一个自动指标下结论会翻车。画面验收必须「自动判据 + 目视抽帧」双轨。
- 关键结论必须有**双向样本**。P24 曾因只采到单向 SPS 把通道映射判反，导致整版失败。
